## 🟢 Quick wins（半天內，最先做）

### A. 必填欄位 inline 紅框錯誤訊息

**為什麼**：目前 `onSave` 跑 `validatePage` 失敗只跳 `ElMessage` toast，使用者不知道哪個欄位錯。

**怎麼改**：
- `useDynamicPages.ts` 的 `validatePage` 已回傳 `errors[]` 含 `field` 跟 `message`
- `AddEditView.vue` 加一個 `errors = ref<Record<string, string>>({})`，validate 失敗時把 `errors[field] = message`
- 對應欄位下方加：
  ```vue
  <span v-if="errors.title" class="field-error">{{ errors.title }}</span>
  ```
- input `@input` / `@blur` 時 clear 該 field 的 error
- 既有 `.required::after { content: ' *' }` style 可以延伸成「錯誤時整個 input 紅框」

**檔**：`PageManagement_AddEditView.vue` line 47-79（基本欄位區）

### B. slug 即時衝突警告

**為什麼**：現在 `validatePage` 才查 `isSlugConflict`，使用者填到最後一刻才知道。

**怎麼改**：
- `el-input` slug 加 `@input` debounced 350ms 後 call `isSlugConflict(form.slug, form.id)`
- 衝突時 input 旁顯示 ⚠️ 紅字「已有頁面用這個 slug」
- 用 lodash debounce 或自己寫 setTimeout

**檔**：`PageManagement_AddEditView.vue` line 60-69

### C. 預覽 loading 狀態強化

**為什麼**：前端 `pages/preview.vue` 開啟後若 dev server 沒跑、postMessage 沒進來，會卡在「📡 等待後台連線中」沒提示。

**怎麼改**：
- 後台 `PreviewPane.vue` 開 iframe 時設 timeout 3 秒
- 3 秒內沒收到前端 `preview:ready` 回應 → 顯示「無法連線到前端，請確認 localhost:3000 是否在跑」+ 重試按鈕
- 收到 ready 後正常運作

**檔**：`PageBuilder/PreviewPane.vue`

### D. publishTime / unpublishTime 衝突檢查

**為什麼**：使用者可能填結束時間早於開始時間，目前沒檢查。

**怎麼改**：
- 在 `validatePage` 加一條檢查 `if (publishTime && unpublishTime && new Date(unpublishTime) <= new Date(publishTime))` 回傳錯誤
- 或者：unpublishTime el-date-picker 加 `:disabled-date` 不讓使用者選比 publishTime 早的日期

**檔**：`useDynamicPages.ts` 的 validatePage + `AddEditView.vue` line 170-194

### E. 儲存成功後不要直接跳走（新增頁時）

**為什麼**：`onSave` 在 isAdd 時 `GuideToPage('PageManagement_DataList')` 直接跳列表，使用者想繼續調整就要重新進來。

**怎麼改**：
- 改成「儲存成功後停留在編輯頁」：
  - `form.id` 填回 insert 回傳的 id
  - URL 改成 `?id=xxx`（用 router.replace）
  - `isAdd` 內部變數切 false
  - toast「頁面已新增，繼續編輯或回列表」+ 「回列表」按鈕
- 編輯模式（非 isAdd）本來就停留，邏輯一致

**檔**：`PageManagement_AddEditView.vue` line 598-606

## 🟡 中型（1-2 day）

### F. autosave 草稿到 localStorage

**為什麼**：意外關 tab / 瀏覽器 crash 會掉資料。`beforeunload` 只提示，不存。

**怎麼改**：
- watch `form` deep，30 秒間隔 + blur 時 `localStorage.setItem('pm_draft_' + form.id, JSON.stringify(form))`
- 進編輯頁時檢查有沒有 draft：
  - 有：跳 dialog「偵測到未儲存的草稿（XX 分鐘前），要還原嗎？」
  - 還原：`Object.assign(form, draft)`
  - 放棄：刪掉 localStorage key
- `onSave` 成功後刪掉 draft
- 避免 localStorage 撐爆：只存最近 5 個 draft，超過清最舊

**檔**：`PageManagement_AddEditView.vue` 加新 `useAutosave` composable

### G. 預覽 viewport 切換（桌面 / 平板 / 手機）

**為什麼**：設計師 / 內容人想看 RWD 表現，現在 preview iframe 寬度固定。

**怎麼改**：
- `PreviewPane.vue` 加三顆切換按鈕 `[桌面 / 平板 / 手機]`
- 不同 mode iframe 寬度：桌面 100%、平板 768px、手機 414px
- iframe wrapper 加 max-width 跟 transition
- 桌面 / 平板 / 手機 切換時 postMessage 不變，純前端 CSS 縮放

**檔**：`PageBuilder/PreviewPane.vue`

### H. DataListView 批次操作

**為什麼**：sheet2 #42 後台 backlog，多選 + 批次發布/下架/刪除/複製 大幅省時間。

**怎麼改**：
- `PageManagement_DataListView.vue` 在 `<el-table>` 加 `<el-table-column type="selection">`
- 表頭加批次操作 bar：選了 N 筆 → 「批次發布 / 批次下架 / 批次刪除 / 批次匯出」
- 每個操作配 confirm dialog（用 `ElMessageBox.confirm`）+ progress（如果 N > 5）
- `useDynamicPages` 加 `bulkUpdate / bulkDelete / bulkPublish` method

**檔**：`PageManagement_DataListView.vue` + `useDynamicPages.ts`

### I. 複製既有頁

**為什麼**：類似頁面（如「2026 年活動 → 2027 年活動」）省去重輸入。

**怎麼改**：
- `DataListView` 每筆 row 加「複製」icon
- click：`useDynamicPages` 新 method `duplicate(id)`：
  - 拿原頁，深拷貝
  - `id` 重新生
  - `title` + ` (副本)`
  - `slug` + `-copy` 或 `-copy-N`（檢查衝突）
  - `status` 強制 'draft'（不要意外發布到正式站）
  - `createDate` / `updateDate` 重設為 now
- 跳到編輯頁 `?id=新id`

**檔**：`PageManagement_DataListView.vue` + `useDynamicPages.ts`

### J. 版本歷史 / 還原

**為什麼**：sheet2 #51。誤改可救回，跟設計溝通有依據。

**怎麼改**：
- 每次 `onSave` 把 snapshot 推進 history array（存 localStorage 或後端 API）

- localStorage 只能存最近 10-20 個版本；要久要後端 DB

**需先**：跟主管確認存哪（localStorage / 後端 DB / 兩者）

### K. 圖片上傳元件

**為什麼**：cover image / og image 現在是 input URL，使用者得先去其他工具上傳再貼回，不直覺。

**怎麼改**：
- 換成 `<el-upload>` drag-drop + 預覽
- 後端 API 要新 endpoint `/api/upload-image` 收 multipart/form-data，回傳 URL
- 加格式 / 大小檢查（sheet2 #23）：accept image/*, max 5MB
- 上傳進度條（sheet2 #54）

**需先**：跟後端確認 endpoint + 儲存位置（S3 / VM 本地 / Google Drive）

### L. SEO 預覽 mockup

**為什麼**：使用者沒概念實際 SEO 結果長怎樣，metaDescription 寫得不好。

**怎麼改**：
- `PreviewPane.vue` 加「預覽模式」切換：頁面預覽 / Google 搜尋結果 / FB 分享 / LINE 分享
- Google 搜尋預覽：白底卡片，title + URL + meta description，模擬 SERP
- FB 分享預覽：og:image + og:title + og:description，藍框卡片

**檔**：`PageBuilder/PreviewPane.vue` 加 mode switcher

## 注意事項

- **避免一次大改**：每做完一條 commit + push 一次，方便回退
- **保持向後相容**：`useDynamicPages` 的資料結構（DynamicPage type）不要動 schema，避免之前儲存的頁面壞掉
- **localStorage key 命名**：用 `pm_` 前綴避免跟其他模組衝突
- **autosave debounce**：30 秒太頻繁可改 60 秒，太久可能掉資料
- **批次刪除**：一定要 confirm dialog 列出被影響項目（sheet2 #21 的精神）
