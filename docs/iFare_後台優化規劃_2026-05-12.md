# iFare 後台優化規劃（2026-05-12）

> 依 `docs/iFare_問題追蹤與AI維運規劃.xlsx` 主題二 sheet 整理。本文為**規劃文件**，提供階段切分與時程估算，給 Emma 與主管／後端團隊討論優先順序，非實作藍圖。

## 摘要

- **後台 backlog 總數**：54 條「待處理」
- **優先級分布**：20 高 / 27 中 / 7 低
- **領域分布**：共用元件 16｜後台通用 14｜其他（圖片/帳號/權限/檔案/側邊欄/Dashboard/Code 管理/HTML 編輯器…）24
- **建議切三階段**：第一階段（快做）→ 第二階段（中期重構）→ 第三階段（架構改造）

完成後預估能大幅改善：載入回饋一致性、表格操作效率、CRUD 表單體驗、權限管理可維護性、Dashboard 工作流。

### 尚未完成但仍建議優先

| 項目 | 建議原因 |
|---|---|
| 新增頁 inline 欄位錯誤 | 使用者最容易卡在不知道哪個欄位錯 |
| slug 即時衝突警告 | 避免最後儲存才發現網址重複 |
| publish / unpublish 時間衝突檢查 | 避免排程設定錯誤 |
| autosave 草稿 | 避免長表單或 PageBuilder 編輯途中資料遺失 |
| PageBuilder 正式 .NET API | 上遠端主機前可先用 Nuxt bridge，但正式化仍需後端儲存 |

## 第一階段：立即可做（3-5 個工作天，Emma 可獨立完成）

挑「高優先 + 做得快 + 不容易錯」的 6 條，先把使用者每日會碰到的痛點修掉：

| # | 標題 | 影響 | 估時 |
|---|---|---|---|
| 3 | 後台通用 — 統一 loading / success / failure 回饋機制 | 全後台一致回饋體驗，使用者不會卡在「儲存了沒？」 | 0.5 day |
| 20 | 共用元件 — 搜尋條件清除功能 | 不必逐欄清空或刷新頁面 | 0.3 day |
| 26 | 日期選擇 — 日期範圍快捷選項（本週 / 本月 / 最近 30 天） | 篩選快很多 | 0.3 day |
| 28 | 共用元件 — 分頁大小變更後自動回第 1 頁 | bug fix，避免頁碼超出範圍空白 | 0.2 day |
| 42 | 共用元件 — 表格批次操作（多選 + 批次刪 / 啟用 / 匯出） | 操作效率大幅提升 | 1 day |
| 54 | 共用元件 — 匯入匯出進度提示 | 大檔案不會以為當機 | 0.3 day |

**合計**：~2.6 work days

**先決條件**：無，直接做。

**2026-05-19 補充**：#20、#26 已完成；#3 已在 PageBuilder 儲存流程先落地，但尚未成為全後台共用規格。#42、#54 仍建議保留在下一批。

## 跟主管討論點

1. **第一階段剩餘項目是否繼續做？**
   - 已完成：#20、#26
   - 部分完成：#3
   - 建議下一批：#42、#54，以及表單防呆 #18/#21/#23
2. **第二階段「#1 CRUD 高層模板」要不要做？**
   - 做：所有共用元件都會被影響，但長期維護便宜很多
   - 不做：每個新功能繼續複製貼上
3. **第三階段哪幾條優先？**
   - 權限改造（#6）影響面最大，但風險也最高 — 需要主管授權做、後端配合
   - Dashboard 重構（#39-#41 + #53）對使用者最有感
   - audit log（#50）+ 軟刪除（#52）= 資安合規必備
4. **跨議題**：#8 / #14 / #16 三條建議跟後端團隊開個 30 分鐘討論
5. **時程**：Emma 週一 / 週二可用，依此估算每月可消化幾條

## 2026-05-19 後續建議

若接下來要先上遠端主機，建議今天之後先做「低風險收尾」：

1. commit / push 目前文件與 UIUX 收尾成果。
2. 遠端部署先確保 `server/data/dynamic-pages.json`、`server/data/dynamic-assets/` 不被覆蓋。
3. 不在上線前大改 CRUD 高層模板、權限邏輯、WebAPI 拆分。
4. 下一批再做新增頁 inline validation、slug 即時檢查、autosave 草稿。
5. 正式 API / DB schema 等大改動先列入主管與後端會議。
