# AI 維護中心下一步規劃

> 目的：把目前的 `AI 維護中心` 從「報告看板」升級成「後台人員可以下指令、整理任務、同步 Excel、再依任務執行」的工作台。

## 1. 目標

我希望後台人員可以直接跟 AI agent 說需求，例如：

- 幫我整理今天要處理的維護問題
- 幫我把這些問題加入後台任務清單
- 幫我同步到 Excel
- 幫我重新產出報告
- 幫我根據任務內容開始執行修改

AI agent 不是直接亂改，而是先整理成任務，經過確認後再執行白名單內的操作。

## 2. 現況

目前已完成的能力：

- 後台有 `AI 維護中心`
- 可以看最新維護報告
- 可以看高優先待辦
- 可以查 audit log
- 可以用本機 runner 執行白名單任務
- 報告可輸出到桌面 `Word / Markdown`

目前還缺的能力：

- 任務收件匣
- 任務整理與分類
- 任務寫入後台資料
- 任務同步到 Excel
- 任務確認與執行狀態
- 修改時的工作流程

## 3. 你想要的使用流程

### 3.1 新需求進來

後台人員在 `AI 維護中心` 輸入一句話，例如：

- 這幾個頁面的說明太長，幫我整理成簡短版本
- 今天先處理高優先後台優化項目
- 幫我把這些問題整理成任務，明天再看

AI agent 先把這句話整理成結構化任務，而不是直接執行。

### 3.2 形成任務

AI agent 產出一筆任務，內容至少包含：

- 標題
- 來源描述
- 類別
- 優先級
- 狀態
- 建議下一步
- 是否需要人工確認
- 是否能同步到 Excel

### 3.3 同步資料

任務建立後，同步到兩個地方：

- 後台任務列表
- Excel 追蹤檔

這樣後台和 Excel 會有一致的工作視圖。

### 3.4 確認後執行

當任務需要實際修改時：

- 先顯示任務摘要
- 讓使用者確認
- 由 agent 執行白名單內的動作
- 執行結果回寫 audit log
- 更新任務狀態

## 4. 建議的任務狀態

任務至少要有這些狀態：

- `new`：剛建立
- `triaged`：已整理
- `pending_review`：等待確認
- `approved`：已核准可執行
- `running`：執行中
- `done`：完成
- `failed`：失敗
- `blocked`：卡住，需要人介入

## 5. 建議的資料結構

### 5.1 任務卡

```json
{
  "id": "TASK-2026-05-26-001",
  "title": "整理今日高優先後台待辦",
  "source": "後台人員輸入",
  "category": "backend-optimization",
  "priority": "high",
  "status": "pending_review",
  "requestText": "幫我整理今天要先做的後台優化",
  "summary": "從 Excel 和報告中整理出 5 個高優先項目",
  "nextAction": "同步到後台任務列表與 Excel",
  "needsApproval": true,
  "createdAt": "2026-05-26 16:00:00",
  "updatedAt": "2026-05-26 16:00:00"
}
```

### 5.2 audit log

每次 agent 動作都記錄：

- 誰觸發
- 做了什麼
- 用了哪個任務
- 成功或失敗
- 產出檔案位置
- 耗時

## 6. 建議的系統切分

### 6.1 後台 UI

`AI 維護中心` 建議拆成：

- 狀態區
- 指引區
- 快速任務區
- 任務收件匣
- 任務詳情
- 執行結果
- audit log

### 6.2 Runner

本機 runner 保持白名單，只負責：

- 產報告
- 預覽報告
- 驗收檢查
- 查詢狀態
- 以任務為單位執行受控操作

### 6.3 Excel

Excel 不直接當作「輸入畫面」，而是做為：

- 追蹤清單
- 任務同步來源
- 人工審核參考

## 7. 建議的 API / 流程

可以用這種方向拆：

```text
POST /agent/intake
POST /agent/tasks
GET  /agent/tasks
PATCH /agent/tasks/:id
POST /agent/tasks/:id/approve
POST /agent/tasks/:id/run
GET  /agent/audit
POST /agent/report
```

如果現在不想做太多 API，至少先做：

- 任務建立
- 任務列表
- 任務狀態更新
- 產報告

## 8. 白名單原則

AI agent 可以做的事要先寫清楚：

- 讀專案
- 讀 Excel
- 建立任務
- 更新任務狀態
- 產出報告
- 寫 audit log

AI agent 先不要直接做：

- 任意改程式碼
- 任意寫 Excel 任意欄位
- 任意 push / deploy
- 任意呼叫正式環境 API

## 9. 建議實作順序

### 第一階段

- 把使用者輸入整理成任務
- 顯示任務列表
- 存到本機 JSON
- 同步 audit log

### 第二階段

- 任務可手動核准
- 核准後才執行
- 可同步到 Excel

### 第三階段

- 任務可依規則自動分類
- 可從報告直接產生待辦
- 可連動提醒與排程

### 第四階段

- 加上更完整的對話式操作
- 加上任務追蹤頁
- 加上執行歷史與回溯

## 10. 驗收標準

這版做完後，至少要能做到：

- 後台人員可以輸入一句話
- AI 會整理成任務卡
- 任務卡會出現在後台
- 任務可以同步到 Excel
- 任務可以確認後執行
- 執行結果會寫 audit log
- 執行結果可以回頭查

## 11. 目前最適合先做的三件事

1. 任務收件匣
2. 任務確認與執行
3. 後台與 Excel 的同步紀錄

## 12. 結論

這不是單純「報告工具」而已。
如果下一步照這份規劃做，`AI 維護中心` 會變成：

- 可以接需求
- 可以整理需求
- 可以排優先順序
- 可以確認後執行
- 可以留紀錄
- 可以同步到 Excel

也就是一個真正能用的後台 AI 助理工作台。
