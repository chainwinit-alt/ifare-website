# 搜尋相關性回歸工具

這兩支腳本對應 v.1.7.13 加進後端的「主題落地檢查」（`iFare_Frontend_API` 的
`FarePolicyTaskManager.HasGroundedSearchTopic`）：站內完全沒有的主題（例如「寵物醫療補助」）
不再靠「醫療」「補助」這類高頻字撐過相關性門檻、撈回幾百筆弱相關（實測 565 筆），
而是直接回 0 筆，讓前端「查無資料」的引導流程（`overview_general`）接手。

**改過檢索計分、門檻、泛用詞清單，或後端 API 換版前後，都應該跑一次這裡的腳本。**

---

## 前置條件

政策 API 跑在 `http://localhost:8082/api/services/app`（跟 `scripts/llm-qa-bench` 同一套，
注意沒有 `/ifare_api` 路徑前綴）。要指到別的環境，設環境變數 `IFARE_API_BASE`。

跑之前先 `cd` 到這個目錄。

---

## search-suite.mjs — 前後筆數對照

兩組查詢：**站內沒有的主題**（寵物醫療補助、電動車充電樁⋯）應回 0 筆；
**站內真實主題**（假牙、長照、新北市老人津貼⋯）筆數與排名第一筆不能變。

```bash
node search-suite.mjs > baseline.json          # 改動前：存基準
node search-suite.mjs --compare baseline.json  # 改動後：逐項對照，有回歸就 exit 1
```

基準檔是**資料相依**的（政策上下架筆數就會變），不要進版控；要改動的當天抓當天的基準。

## gate-sim.mjs — 落地規則模擬

`HasGroundedSearchTopic` 的 JS 對照實作：抓全量政策當語料，跑 30 個案例
（該擋的怪詞、該放行的正常詞、混合查詢、泛用詞切段等），全過才 exit 0。

```bash
node gate-sim.mjs
```

**改 C# 規則（泛用詞清單、切段字元、二字組鏈邏輯）時，這裡要同步改**，兩邊清單
不一致時以 C# 為準、以這裡的案例為驗收。要加新的邊界案例，改檔案底部的 `CASES`。

---

## 規則摘要與已知取捨

規則：查詢依空白／標點切段 → 每段再依泛用詞（補助、津貼、福利⋯）切成具體片段 →
任一片段（兩字以上）的**每個相鄰二字組**都在政策庫全文出現過即放行；全部片段都
不落地才回 0 筆。站內存在的主題，計分與排序完全不動。

刻意不用斷詞器：JiebaNet 詞典偏簡體，繁體「寵物」會被切成單字而漏判（第一版
用斷詞就是這樣失敗的，見 v.1.7.13 commit 訊息）。

已知取捨（都有下一層接住）：

- **錯字直打後端**（「老任津貼」）回 0 筆——正常流程中前端 `fixCommonTypos` 與
  意圖判讀會先修字。
- **整句問話直打後端**（「我媽媽80歲想裝假牙」）回 0 筆——UI 是雙路查詢，
  AI 意圖那一路會帶核心詞去查，實測 UI 整句搜尋正常。
