# 搜尋品質評估工具

用一組固定的「使用者實際會怎麼問」的題目打政策 API，把搜尋好不好用換算成數字，
讓每次檢索改動都能拿前後兩個分數對照，而不是憑手邊幾個例子的印象。

起因：判斷搜尋有沒有變好一直靠人工試幾句，實測 8 句候選問法裡有 2 句回 0 筆，
是試到才發現的。這種漏接應該被工具抓出來，不是靠運氣。

---

## 前置條件

政策 API 跑在 `http://localhost:8082/api/services/app`（跟 `scripts/llm-qa-bench`、
`scripts/search-relevance` 同一套，注意沒有 `/ifare_api` 路徑前綴）。
要指到別的環境，設環境變數 `IFARE_API_BASE`。

純 Node ESM，沒有任何 npm 相依，`cd` 到這個目錄直接跑。

---

## 怎麼跑

```bash
node eval.mjs                          # 跑一次，印總表與總分
node eval.mjs --json before.json       # 改動前：存基準
#   ...改檢索邏輯 / 換 API 版本...
node eval.mjs --json after.json        # 改動後：再跑一次
node compare.mjs before.json after.json  # 逐題對照，有任何一題變差就 exit 1
```

其他參數：

| 參數 | 用途 |
| --- | --- |
| `--cases <path>` | 換一份評估集，預設是同目錄的 `cases.json` |
| `--max-fail <n>` | 容許 N 題失敗仍 exit 0。棘輪用：把目前的失敗數寫進 CI，之後只能往下調 |

`eval.mjs` 只要有題目失敗就 exit 非 0，可以直接當驗收關卡。
**注意目前的基準線本來就是紅的**（見下方「目前的實測基準」），要進 CI 請先用
`--max-fail` 卡住現況，再隨著改善逐步調低。

產出的 json 是**資料相依**的（政策上下架筆數就會變），不要進版控，
要改動的當天抓當天的基準。

## cases.json 各欄位

```json
{
  "query": "我缺錢可以怎麼辦",
  "note": "純處境：完全沒有政策詞彙，只講處境⋯",
  "expectPolicyIds": [],
  "expectKeywords": ["急難", "生活扶助"],
  "expectZero": false
}
```

| 欄位 | 意義 |
| --- | --- |
| `query` | 使用者實際會打的字，原封不動送給 API |
| `note` | **為什麼收這題**。之後看到分數變動時，是靠這句話判斷該不該在意 |
| `expectPolicyIds` | 這題的正確答案政策 id。填了才會算 recall@10 與 MRR |
| `expectKeywords` | 正確答案標題應該出現的關鍵字。`expectPolicyIds` 沒填時的替代判準 |
| `expectZero` | 站內根本沒有這個主題，正確行為是回 0 筆 |

判準依每題的形狀自動決定，三選一：

- **`expectZero: true`** → 通過條件是確實 0 筆。分數 1 或 0。
- **有填 `expectPolicyIds`** → 算 **recall@10**（前 10 名撈到幾個正確答案 ÷ 正確答案總數）
  與 **MRR**（第一個正確答案的排名倒數，排第 1 得 1.0、排第 5 得 0.2、沒撈到得 0）。
  分數取 recall@10，至少命中一個才算通過。
- **只有 `expectKeywords`** → 算「前 10 筆標題含任一關鍵字」的命中率，
  至少命中一筆才算通過。標題比對會做正規化（全半形、大小寫、標點、臺→台）。

總分是所有題目分數的平均。

---

## ⚠ 為什麼 expectPolicyIds 需要人工標註

**現在 20 題的 `expectPolicyIds` 全是空陣列，所以跑出來的數字只是過渡期的粗略參考。**

關鍵字命中率量的是「前 10 筆標題長得對不對」，不是「有沒有把該給的政策給出來」。
它會在兩個方向上騙人：

- **假通過**：查「我缺錢可以怎麼辦」撈回 200 筆標題都有「生活扶助」，命中率 100%，
  但真正該排第一的急難救助排在第 87 名——分數看不出來。
- **假失敗**：撈到的政策完全正確，只是標題用了別的詞（「經濟弱勢家庭兒少生活補助」
  對上關鍵字「急難」），會被算成沒命中。

要讓這套真的能拿來下判斷，得**人工把每題的正確答案 id 填進 `expectPolicyIds`**：
拿 `query` 去站上查，人眼挑出「這題使用者真正該看到的政策」，把 id 抄進去。
一題填 3～10 個 id 就夠，不必窮舉；重點是那幾個「沒撈到就等於答錯」的。
政策 id 直接從 API 結果或 `eval.mjs --json` 存檔的 `rows[].top` 取（格式是 `[id] 標題`）。

填完之後，該題的判準會自動從關鍵字命中率切換成 recall@10 + MRR，
`eval.mjs` 的摘要也會開始輸出「已標註」那一組的數字。`expectKeywords` 可以留著不刪，
填了 id 就不會再用到。

## 評估集收了哪些題目

20 題，六類。除了「站內沒有的主題」與「關鍵詞控制組」，其餘都是目前會漏接的形狀：

| 類別 | 題數 | 例子 | 收案理由 |
| --- | --- | --- | --- |
| 錯字 | 3 | 老任津貼、假芽補助、中低收入護 | 同音錯字最常見，錯一個字就全滅 |
| 口語整句 | 4 | 我媽媽80歲想裝假牙 | 帶稱謂、年齡、數字的完整問句 |
| 純處境 | 5 | 我缺錢可以怎麼辦、房租繳不出來 | 完全沒有政策詞彙，使用者不知道要查什麼才會這樣問 |
| 受助對象對照 | 2 | 我兩個月沒工作 vs 我小孩要註冊沒錢 | 一組對照題，兩題若撈回同一份清單代表沒讀出受助對象 |
| 站內沒有的主題 | 3 | 寵物醫療補助、電動車充電樁、健身房會員補助 | `expectZero`，防止放寬檢索時誤放行 |
| 關鍵詞控制組 | 3 | 假牙、長照 喘息服務、新北市 老人津貼 | 基本查詢不能為了處境查詢被弄壞 |

「健身房會員補助」是刻意放的難題：它帶了「補助」這個泛用詞，
是放寬檢索後最容易誤放行的形狀。

## 目前的實測基準

2026-08-26 對本機政策 API 實跑：

```
總分 30%　通過 6/20
  站內沒有的主題　正確回 0：3/3
  已標註 id　　　 通過 0/0　recall@10 0%　MRR 0.00
  僅關鍵字　　　　通過 3/17　有結果 3/17　命中率 17%
```

失敗的 14 題**全部是 0 筆**——錯字、口語整句、純處境、受助對象四類無一倖免，
只有關鍵詞控制組跟 `expectZero` 三題是通過的。

這不完全是 bug：後端 v.1.7.13 的主題落地檢查（`HasGroundedSearchTopic`）會擋掉
含站內不存在二字組的查詢，錯字與整句問話直打後端本來就回 0，
正常流程是前端 `fixCommonTypos` 與 AI 意圖判讀先把核心詞取出來再查
（見 `scripts/search-relevance/README.md` 的「已知取捨」）。

**這套工具量的是政策 API 這一層。** 這 30% 就是「使用者的原句直接丟給檢索」的真實能力，
也是這份基準的意義：整句理解如果哪天要往後端搬、或前端修字規則要擴，
改完再跑一次就知道有沒有真的往上走。要改成量端到端（含前端修字與意圖判讀）的體驗，
把 `IFARE_API_BASE` 指到包含那層處理的端點即可，`cases.json` 不用動。

## 這套與 search-relevance 的分工

| | `scripts/search-relevance` | `scripts/search-eval`（這裡） |
| --- | --- | --- |
| 回答的問題 | **有沒有退步？** | **有沒有變好？** |
| 判準 | 筆數與排名第一筆跟基準一致 | 正確答案有沒有被撈到、排第幾 |
| 資料 | 寫死在腳本裡的查詢分組 | `cases.json`，可持續擴充 |
| 什麼時候跑 | 改計分、門檻、泛用詞清單、API 換版 | 同上，加上任何想證明「這樣改比較好」的時候 |

兩套是互補的，都要跑：

- `search-relevance` 保守——**筆數變了就算回歸**，所以它擋得住「不小心弄壞」，
  但你為了讓「我缺錢可以怎麼辦」有結果而放寬檢索時，它一定會亮紅燈，
  那是預期內的，該重抓基準。
- `search-eval` 進取——**它不在乎筆數，只在乎有沒有找到對的東西**。
  放寬檢索讓 14 題從 0 筆變成有命中，只有這裡看得到分數上升。

實務順序：先跑 `search-eval` 確認改動真的有效（總分上升、沒有題目變差），
再跑 `search-relevance` 確認控制組沒被波及、該 0 筆的還是 0 筆。

`compare.mjs` 刻意設計成**只要有任何一題變差就 exit 1**，即使總分是上升的——
「總分變高」不能拿來換「某幾題壞掉」。
